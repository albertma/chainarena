# 用例 01：注册建号（Sign Up）—— 60 秒从链接到首局

> 生命周期位置：访客 → 正式选手 ｜ 参与者：新玩家、Paymaster（新手赞助档）、Sensei-青铜（首局对手）
> 前置条件：**无**——不需要钱包、不需要 ETH、不需要助记词、不需要预注册
> 成功保证：60 秒内打完第一局；全程 0 Gas；共 2 次签名（建号 + 会话授权）
> 上游依据：产品 §1.4 / §3.1；技术 §4.2 / §4.3 / §4.4 / §7.2

## 1. 触发与入口

- 落地页/好友分享链接 → 「用 Face ID 开始」按钮
- 无任何前置：注册即建号即开局，三件事一笔完成

## 2. 主流程（成功路径）

```
① [用 Face ID 开始]
   → navigator.credentials.create() 生成 passkey（secp256r1）
   → 1 次系统生物识别确认（非钱包弹窗）

② CREATE2 预计算账户地址（纯本地，不上链）
   → 地址确定且稳定（即使中途放弃，下次还是同一地址）

③ 组装首笔 UserOp（passkey 签名，1 次签名）：
   executeBatch [
     部署 Safe 账户（initCode，惰性部署在此刻触发）
     claimStarter()      ← 领取新手 Fighter（VRF 定配置）+ 新手赠币（数额为运营配置）
     createMatch(休闲)   ← 对手自动匹配 Sensei-青铜
   ]
   → 向策略服务请求 Paymaster 策略签名 → paymasterAndData = 新手赞助档
   → eth_sendUserOperation → Bundler → EntryPoint → 上链（~2s 软确认）

④ 比赛会话授权（passkey，第 2 次签名）
   → grantSession(会话密钥, 规则 = 本局 + 30min 缓冲 / 60 招上限 / 出招类 selector)
   → 会话密钥存 IndexedDB；此后整局 0 弹窗

⑤ 打首局（流程见用例 05）
```

## 3. 状态与数据变化

| 对象 | 之前 | 之后 |
|---|---|---|
| 账户 | 不存在（CREATE2 地址空置） | Safe 已部署，owner = passkey 公钥 |
| Fighter | 无 | 1 个新手 Fighter（VRF 配置 = 流派 + 三系标签，见用例 04） |
| 货币 | 无 | 新手赠 $ARENA（运营配置数额） |
| 对局 | 无 | 1 场进行中的休闲局（vs Sensei-青铜） |
| 密钥 | 无 | passkey（硬件安全区）+ 比赛会话密钥（IndexedDB） |

## 4. 体验要点

| 指标 | 目标 |
|---|---|
| 总耗时 | ≤ 60 秒（点开链接 → 打完首局） |
| 弹窗 | 2 次签名（① passkey 创建、④ 会话授权），出招 0 弹窗 |
| Gas | 玩家 $0；运营侧首局成本 ~600k gas ≈ $0.02–0.05（新手赞助 50 局 / 7 天内全免） |
| 等待感 | 乐观 UI：③ 上链期间按钮锁定显示「正在为你安排对手」 |

## 5. 异常与边界

| 情形 | 处理 |
|---|---|
| 设备不支持 passkey（低端安卓，风险 Q2） | fallback 邮箱验证器（W3 设备矩阵测试覆盖） |
| 首笔 UserOp 失败（AA10x 网络） | 客户端自动重试；地址不变、passkey 不变 |
| 中途关闭页面 | passkey 与地址留在本地；下次打开继续（② 的地址确定性保证） |
| 女巫批量注册 | 赞助档防线：每账户每日 ≤ 3 局休闲赞助、账户年龄、设备指纹、金库日预算熔断 |
| Passkey 创建后永远不上链 | 无成本：链上无状态，本地数据可弃 |

## 6. 权限与安全

- 签名层级：全程 **L2 passkey**（建号与会话授权均为价值/敏感操作）
- 赞助范围：仅 MatchCore 白名单 selector（技术 §4.4），不可能被引流到任意调用
- 首笔原子性：部署 + 领取 + 开局一笔完成，无"部署了却没领到 Fighter"的中间态
