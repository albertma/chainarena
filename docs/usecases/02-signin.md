# 用例 02：登录（Sign In）

> 生命周期位置：横切流程（任意会话进入） ｜ 参与者：回访玩家、游戏 API
> 前置条件：已完成注册（用例 01），本机或他机持有可用的账户凭证
> 成功保证：0 钱包弹窗进入登录态；JWT 有效期内回访完全静默
> 上游依据：产品 §3.2；技术 §4.7（ERC-1271）

## 1. 触发与入口

- 打开站点（同设备回访）
- 从落地页/分享链接进入需要登录态的页面（战绩、雇佣代打、领奖）

## 2. 主流程（成功路径）

```
① 打开站点 → 客户端检查本地凭证（IndexedDB）
   ├─ JWT 未过期 → 静默续期，直接进入（最常见路径，0 交互）
   └─ JWT 过期/缺失 → 走 ②

② 向游戏 API 请求一次性 nonce：GET /auth/nonce

③ 组装签名消息（SIWE 风格）：域名 + 账户地址 + nonce + 过期时间

④ 账户签名（ERC-1271）
   → 优先复用本地有效签名凭证（如仍在有效期的比赛会话密钥）静默完成
   → 无可用凭证时：passkey 快速生物识别（系统级确认，非钱包交易弹窗）

⑤ 后端校验：调用账户 isValidSignature（对已部署账户可直接链上/模拟验证）
   → 通过 → 签发 JWT（短期访问令牌 + 刷新令牌）
   → nonce 一次性作废（防重放）

⑥ 进入游戏；后续 API 请求携带 JWT
```

## 3. 状态与数据变化

| 对象 | 之前 | 之后 |
|---|---|---|
| 登录态 | 无/过期 | JWT 有效（客户端本地持有） |
| 后端 `players` 表 | 无会话记录 | 记录账户、登录时间、设备 |
| 链上 | — | **无任何链上写入**（纯链下验签，0 Gas） |

## 4. 体验要点

- 弹窗：**0 钱包弹窗**（产品 §3.2 策略表）；仅在全凭证过期时出现一次系统级生物识别
- 耗时：静默路径 < 1s；nonce+签名路径 2–3s
- 费用：$0（无链上交易）

## 5. 异常与边界

| 情形 | 处理 |
|---|---|
| 换新设备（无任何本地凭证） | 账户支持多 passkey：需在已登录设备上添加新 passkey；若无可信设备 → 走用例 03 恢复 |
| 账户从未上链（注册中途放弃） | 后端按 CREATE2 预测地址处理，引导完成注册首笔 UserOp |
| nonce 重放 | 一次性 nonce + 短时效签名消息 |
| 后端伪造登录 | 验签在链上合约/确定性模拟完成，后端无法冒签（JWT 只发放给持有签名者） |
| 进行中对局中 JWT 过期 | 对局不受影响（出招走会话密钥，不依赖 JWT）；观战数据走公开 API |

## 6. 权限与安全

- 签名层级：L1（会话密钥复用）或 L2（passkey），登录本身不产生任何资产操作权限
- JWT 与链上权限完全解耦：JWT 只授权读/撮合等 API 能力，**不能**触发链上转账

## 7. 规格待定项

- 0 弹窗登录的凭证复用策略（JWT 有效期、静默续期阈值、会话密钥可否签登录 nonce）需在客户端设计细化时钉死
