# 用例 07：战后掉落（Lucky Drop —— 武器与护甲）

> 生命周期位置：对局结算的奖励延伸（W10+，与 Gear.sol 同期上线） ｜ 参与者：玩家（被动接收）、MatchCore/Gear 合约、resolve 触发方（bot/任何人）
> 前置条件：完成一局对局（用例 05 终局）；无需任何玩家操作与签名
> 成功保证：掉落结果**任何人（含运营/Sequencer/双方玩家）都无法操纵或预测**；掉落并入 endMatch 原子结算，玩家 **0 签名、0 弹窗、0 Gas**
> 上游依据：产品 §2.5 / §2.6（装备与经济）；技术 §3.1（Gear.sol）、§3.3（endMatch）、§5.5（随机数方案选择）

## 0. 定位：装备的第二条获取通道

装备（ERC-1155）有两条获取路径，互为对照：

| 路径 | 方式 | 成本 | 确定性 | 体验 |
|---|---|---|---|---|
| 锻造（用例 06 ③） | `craft(gearId)` | $ARENA（部分销毁 = sink） | 定向指定 | 1 次 passkey |
| **掉落（本用例）** | endMatch 批内 roll + mint | 免费 | 随机惊喜 | **0 签名 0 弹窗** |

掉落承担「惊喜与留存」：让每一局终局结算都多一层期待；锻造承担「定向与 sink」：想要哪件花钱买。两者共享同一装备池与数值表（game-config，configHash 锚定）。

## 1. 触发与入口

| 触发 | 入口 | 动作 |
|---|---|---|
| 排位局 endMatch | 结算批内自动 roll | lootSeed 掉落判定 → `Gear._mint`（玩家 0 操作） |
| 休闲局 endMatch（含 Sensei 对手） | 同上 | 掉率大幅降档（防刷，见 §6） |
| （对照）主动获取 | 大厅 →「锻造」（用例 06 ③） | `craft(gearId)` 定向付费 |

MVP 装备池即 06 的 6 件套：**武器 3 + 护甲 3**（固定属性）；掉落从池内按权重抽取。

## 2. 主流程（成功路径）

### ① 随机源：免费复用对局本身的 commit-reveal 熵

```
取终局时最近一个「双方均已 reveal」的回合 r：
lootSeed = keccak256(salt0(r), salt1(r), matchId)
```

- 两个 salt 在双方 commit 阶段即锁定，事后**任何一方（含运营/Sequencer）都无法操纵**——与 Fighter 铸造用 VRF 的防操纵目标等价，但零成本
- 想通过「扣住不 reveal」扭曲掉落？扣 reveal = 当回合判负（用例 05 规则）——操纵代价 = 输掉当回合，恒大于一件装备的期望价值
- 方案选择遵循技术 §5.5 的原则一以贯之：**高频、中等价值 → 协议内建随机**；不为每局掉落单独付 VRF 的请求费与延迟

### ② roll 与铸发（并入 endMatch，一笔原子）

```
endMatch 批内:
  结算奖池 / Elo / XP（用例 05 ⑤，不变）
  → rollDrop(lootSeed, 胜负结果):   是否掉落 + gearId（按权重表）
  → 命中 → Gear._mint(玩家账户, gearId, 1)      ← ERC-1155，被动到账
  → 事件 GearDropped(matchId, player, gearId, rarity)
```

### ③ 掉落表（示例参数，全部 configHash 锚定，赛季可调不动合约）

| 结果 | 排位胜者 | 排位败者 | 休闲（真人） | 休闲（Sensei） |
|---|---|---|---|---|
| 不掉落 | 75% | 92% | ≥95% | ≥98% |
| 武器（白/蓝权重） | 共 ~17% | 共 ~5% | 共 ~3% | 共 ~1% |
| 护甲（白/蓝权重） | 共 ~8% | 共 ~3% | 共 ~2% | 共 ~1% |

稀有度分层（白/蓝/紫）为 V2 扩展；MVP 仅白/蓝两档。

### ④ 到账与展示

```
客户端监听 GearDropped → 终局结算页追加「战利品」闪光开箱（复用揭晓动画风格，不新增等待窗口）
→ 装备进入背包（玩家智能账户持有 ERC-1155）
→ 可在市场挂单（产品 §2.6：装备可交易）
```

## 3. 状态与数据变化（以排位胜者掉落为例）

| 对象 | 局前 | 局后 |
|---|---|---|
| ERC-1155 背包 | N 件 | N + 1 件（若命中；未命中则不变） |
| 玩家 UserOps / 签名 | — | **0 新增**（并入 endMatch，Gas 由结算触发方承担） |
| $ARENA | — | 不变（掉落免费——与锻造的付费 sink 形成对照） |
| 链上事件 | — | GearDropped（索引器入背包页 / 战绩页 / 成就页） |

## 4. 体验要点

- 弹窗 / 签名 / Gas：**全 0**——掉落是纯被动事件，这是它相对锻造的体验优势
- 惊喜节奏：KO/回合分结算 → 奖池数字 → 掉落闪光，全部复用终局结算动画时间窗
- 规则透明：客户端展示「本局掉率」与装备池（configHash 校验后渲染），玩家可独立验证每次 roll

## 5. 异常与边界

| 情形 | 处理 |
|---|---|
| 终局回合无完整 reveal（双超时作废局） | 作废局**不掉落**；正常终局但末回合缺 reveal（如 forfeit）→ 回溯最近一个双方已 reveal 的回合取熵 |
| 全程零 reveal（开局秒弃权） | 无可用熵 → 本局无掉落（期望损失极小，不值得为此引入 VRF） |
| forfeit 终局 | 视为正常终局：未弃权方按胜者掉率正常 roll |
| 对手是 Sensei | 掉率降档（女巫防线，见 §6）；真人密度上升后经 configHash 回调 |
| 刷休闲局薅掉落 | 休闲掉率 ≥95% + 每账户每日掉落上限（configHash）+ 女巫标记联动 Paymaster（技术 §7） |
| 装备归属 | ERC-1155 持有人 = **玩家智能账户**（不挂 Fighter）——Fighter 卖出不带走装备；与「XP 随 Fighter、段位随账户」的三权分立保持一致（用例 04） |
| 同件装备重复掉落 | ERC-1155 天然可堆叠（数量 +1）；合成/分解（V2 待定） |
| 掉落 vs 锻造 | 不冲突：共享装备池与数值表，一个免费随机、一个付费定向 |

## 6. 权限与安全

- **玩家侧 0 签名**：掉落由 endMatch 触发方（resolve bot / 任何人）代付 Gas；玩家无任何授权面
- **铸发权限锁死**：`Gear._mint` 仅 MatchCore 可调（结算合约唯一铸发入口，杜绝增发后门；craft 走独立付费入口）
- **随机性防操纵**：lootSeed 的双 salt 均在 commit 期锁定 → 双方玩家、运营、Sequencer 均不可 bias；「扣 reveal 操纵」的代价 = 当回合判负，经济上恒不划算
- **经济防刷**：掉率 / 每日上限 / Sensei 降档均为 configHash 参数，按女巫与经济数据调参不动合约
- **事件冗余**：`GearDropped` 携带全部结果——背包 / 市场 / 成就页零模拟渲染（与 `RoundResolved` 同理念，技术 §3.3）

## 7. 规格待定项

1. 最终掉率与权重表数值——需经济仿真回归（掉落产出 vs 锻造 sink 的平衡，技术 §10 仿真器扩展 loot 曲线）
2. 取熵回溯规则细节（仅回看 1 回合 vs 任意最近完整回合）与回溯上限
3. 稀有度分层（白/蓝/紫）与 V2 赛季限定装备池
4. 重复装备的合成/分解（burn 换 $ARENA，形成新 sink？）与市场版税
5. 高价值局（赛季决赛等）是否升级为 Chainlink VRF 随机（一次性高价值场景，符合技术 §5.5 分界）
